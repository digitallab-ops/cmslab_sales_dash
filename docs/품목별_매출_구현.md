# 품목별 매출 대시보드 — 구현 설명서

> "품목별 매출" 탭이 **어떻게 동작하는지, 왜 이렇게 만들었는지** 정리한 문서.
> (기존 매출 대시보드와 별개의 데이터 파이프라인)

---

## 1. 한 줄 요약

엑셀 5개를 어드민에서 올리면 → **서버가 원본 ~150만 행을 DB에 저장**하고 → **DB에서 집계(68,890건)** 해서 → **/items 탭**에 인터랙티브 대시보드로 보여준다. 원본은 DB에 남아 언제든 조회 가능.

---

## 2. 왜 이렇게 만들었나 (설계 배경)

원본 `품목_대시보드_pilot.py`는 로컬에서 엑셀을 읽어 HTML을 만드는 **독립 스크립트**였다. 이걸 웹앱 탭으로 옮길 때 두 가지 문제가 있었다:

| 문제 | 해결 |
|---|---|
| 원본이 ~150만 행 → 서버(Render 512MB)에서 pandas로 한 번에 올리면 **메모리 초과로 죽음** | 원본은 **스트리밍으로 DB 적재**, 집계는 **DB 커서로 한 행씩** 읽어 누적 → 150만 행을 절대 메모리에 통째로 안 올림 |
| 데이터 모델이 기존 `sales_records`와 완전히 다름 (SKU·채널·품목군 15차원) | **별도 테이블 3개** 신설 (`item_snapshots` / `item_raw` / `item_records`) |
| "원본을 언제든 조회하고 싶다" (요청) | 원본을 `item_raw`에 그대로 저장 → SQL로 아무 때나 조회 |

핵심 원칙: **무거운 건 스트리밍으로, 원본은 DB에, 렌더 로직은 pilot 재활용.**

---

## 3. 데이터 흐름

```
[어드민 패널] 엑셀 5개 업로드
   · 통합매출_2025.xlsx        (원본 거래, ~78만 행)
   · 통합매출_2026.xlsx        (원본 거래, ~78만 행)
   · 공장품목조회.xls          (SKU 마스터: 품목군/분류/브랜드/테마)
   · 관리회계 기준정보.xlsx     (거래처→채널/국가 매핑)
   · 팀참고.xlsx               (채널 노출 순서, 선택)
        │
        ▼
[서버 · 백그라운드 스레드]  save_item_upload()
   1) 마스터 3개 → 임시 dict (작음, 미저장)
   2) 통합매출 xlsx 스트리밍 → item_raw 테이블에 5,000행씩 적재 (~150만 행)
   3) item_raw를 DB 커서(yield_per)로 한 행씩 읽으며:
        - 품목코드로 브랜드/품목군/테마 등 붙이고 (factory 매핑)
        - 거래처코드로 채널/국가/거래처명 붙이고 (customer 매핑)
        - 채널+브랜드로 팀 결정 (resolve_team)
        - 15차원 키로 qty/rev/cost 누적
      → 68,890건을 item_records 테이블에 저장
        │
        ▼
[사용자] /items 접속
   · 권한 체크(can_access_tab "items")
   · item_records를 팀 필터(allowed_teams)로 조회
   · pilot make_html로 25MB HTML 생성 → 캐시 → 응답
[분석가] item_raw 테이블을 SQL로 직접 조회 (원본 언제든 열람)
```

## 4. 새로 만든 것

### 테이블 3개 (`app/models.py`)

| 테이블 | 내용 | 규모 |
|---|---|---|
| `item_snapshots` | 업로드 배치 단위 (기준일, 채널순서, active 여부, 건수) | 업로드마다 1행 |
| `item_raw` | **원본 통합매출** (일자·거래처·품목·수량·매출·원가) | ~150만 행 |
| `item_records` | 15차원 **집계 결과** (대시보드 렌더용) | ~68,890행 |

- `item_snapshots`는 최신 + 직전 1개만 유지(나머지 자동 삭제).
- 테이블은 앱 기동 시 `Base.metadata.create_all`로 자동 생성됨(수동 마이그레이션 불필요).

### 코드 파일

| 파일 | 역할 |
|---|---|
| `app/data/scripts/품목_대시보드_pilot.py` | 원본 pilot **복사본**. 로더·`resolve_team`·`make_html`·`load_chartjs`를 재활용(importlib 로드). |
| `app/data/item_parser.py` | **핵심 파이프라인**. 적재(`ingest_raw`)·집계(`aggregate_from_db`)·조회(`get_active_item_records`)·렌더(`get_cached_item_html`)·오케스트레이션(`save_item_upload`). |
| `app/routes/dashboard.py` | `/items` 라우트 추가 + 상단 네비 페이지 이동 링크. |
| `app/routes/admin.py` | `/admin/upload-items` 엔드포인트(엑셀 5개, 백그라운드 처리). |
| `app/templates/admin.html` | 어드민 "품목별 매출 데이터 업로드" 섹션 + 진행률. |
| `app/tab_registry.py` | `items` 탭 1줄 추가 → 어드민 권한 UI·탭 숨김 자동 반영. |
| `requirements.txt` | `.xls` 읽기용 `xlrd` 추가. |

## 5. 사용법

### 데이터 올리기 (주간/월간)
1. 어드민 패널 → **📂 Excel 업로드** 탭 → **🧴 품목별 매출 데이터 업로드** 섹션
2. 엑셀 5개 선택 (통합매출 2개 + 마스터 3개, 팀참고는 선택)
3. **업로드 & 집계** 클릭 → 진행률(원본 적재 → 집계 → 완료). 수 분 소요.
4. 완료되면 상단 네비바 **품목별 매출** 링크로 확인.

### 원본 데이터 조회 (SQL, 언제든)
```sql
-- 특정 품목의 월별 매출
SELECT date_int/100 AS ym, SUM(rev) AS 매출
FROM sales_dashboard.item_raw
WHERE item_code = 'CFTC0001'
GROUP BY 1 ORDER BY 1;

-- 특정 거래처 거래 내역
SELECT * FROM sales_dashboard.item_raw
WHERE cust_name LIKE '%코스트코%' ORDER BY date_int DESC;
```

## 6. 권한

기존 탭/팀 권한 체계를 그대로 사용:
- **탭 권한**: 어드민 → 사용자/그룹의 "접근 탭"에 `품목별 매출` 체크 여부로 접근 제어. 권한 없으면 /items 403 + 네비 링크 숨김.
- **팀 데이터 필터**: 사용자의 `allowed_teams`가 있으면 해당 팀 데이터만 표시.

## 7. 검증 (구현 시 확인한 것)

- pilot 원본 집계와 신규 서버 집계를 **동일 엑셀로 대조** → 행 수(787,042)·그룹 수(51,901)·매출/수량/원가 합계 **완전 일치**.
- `make_html`이 신규 파이프라인 records로 정상 렌더 확인.
- 신규 테이블·라우트 등록, 전체 모듈 import 확인.

## 8. 주의 / 향후 보완

- **첫 로딩 지연**: 품목 HTML은 ~25MB라 최초 접근 시 몇 초 소요(이후 캐시). 팀별 버전은 캐시 폭증 방지를 위해 최초 접근 시 지연 생성.
- **대용량 업로드**: 통합매출 2개(합 ~55MB) 업로드가 Render 요청 한도에 걸릴 수 있음. 막히면 압축/분할 업로드로 보완 예정.
- **후속 예정**: 품목 스냅샷 set-active/rollback UI, 원본 조회 전용 admin 화면, REST·MCP 노출.
